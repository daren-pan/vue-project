# 健壮性 / 容错设计（Robustness & Fault Tolerance）

> 本文档定义微服务体系的容错能力：幂等、重试与超时、熔断降级、分布式事务、异常体系、缓存与消息可靠性，并给出**错误码规范**与**容错矩阵**。
> 配套文档：[总体架构](00-architecture-overview.md) · [安全架构设计](architecture-security.md) · [扩展性设计](architecture-scalability.md) · [数据与存储设计](architecture-data.md) · [研发全流程](../process/00-overview.md)。

---

## 1. 目标与原则

- **快速失败（Fail Fast）**：参数错误、依赖不可用应快速返回明确错误，而不是挂起拖垮线程。
- **优雅降级（Degrade Gracefully）**：非核心依赖故障时，核心链路降级而非整体不可用。
- **可恢复（Recoverable）**：所有故障都可重试/补偿，数据最终一致，无脏数据残留。
- **默认防御**：入参校验、幂等、超时、限流作为**默认开启**的能力，不允许新接口裸奔。

```
请求 ─► 网关(限流/超时) ─► Service(校验/幂等/事务) ─► 依赖(重试/熔断/降级) ─► DB/Redis/Feign
                                  │
                          GlobalExceptionHandler 统一错误码
```

## 2. 幂等性设计

### 2.1 场景与方案

| 场景 | 幂等方案 | 说明 |
|------|----------|------|
| 支付/回调/审批 | 幂等键（业务单号/回调 ID）+ 幂等表 | 首次写入幂等表，重复请求命中直接返回首次结果 |
| 表单提交/导入 | 前端生成 UUID 请求头 `Idempotency-Key` | Redis SETNX 去重（TTL 与业务窗口对齐） |
| 状态流转更新 | 乐观锁（版本号 / 状态机校验） | `UPDATE ... WHERE id=? AND version=?`，更新失败返回冲突码 |
| 消息消费 | 消费幂等（业务主键去重表） | 见 §10 |

### 2.2 规范

- 幂等键全局唯一（UUID / 时间戳 + 随机数 / 业务单号），不可由前端任意指定后复用。
- 幂等判断与业务写入**必须同库同事务**，避免「判重后未写入」窗口。
- 幂等表按业务分表（`sys_idempotent_<biz>`），定期清理过期记录。
- 涉及金钱/库存/状态机流转的更新一律使用**版本号乐观锁**（见 [AGENTS.md](../../AGENTS.md) 4.6）。

```sql
UPDATE biz_order SET status = 2, version = version + 1
 WHERE order_id = #{orderId} AND version = #{version};
```

## 3. 重试与超时

### 3.1 超时三件套（必须显式配置）

| 层级 | 配置项 | 建议值 |
|------|--------|--------|
| OpenFeign | `connect-timeout` / `read-timeout` | 连接 1~2s，读 3~10s（按接口分级） |
| HTTP 客户端（RestTemplate） | 同上 | 与 Feign 一致 |
| 数据库/Redis | 连接池 `max-wait`、命令超时 | max-wait ≤ 3s，Redis 命令 ≤ 2s |

### 3.2 重试策略（Resilience4j）

- **仅对幂等读/幂等写重试**：非幂等写（扣款、下单）禁止盲目重试，应返回错误由上层补偿。
- 重试上限 2~3 次，指数退避 + 抖动（`exponential-backoff` + `randomized`），避免重试风暴。
- 重试与超时、熔断联动：熔断开启期间不重试。
- 跨服务重试必须携带幂等键，保证重试安全。

```yaml
resilience4j.retry:
  instances:
    default:
      max-attempts: 3
      wait-duration: 500ms
      enable-exponential-backoff: true
      exponential-backoff-multiplier: 2
```

## 4. 熔断降级（Sentinel）

- 使用 Sentinel 对**下游依赖**（Feign 接口、数据库热点查询）配置熔断规则：慢调用比例 / 异常比例 / 异常数阈值触发，熔断窗口 10~30s。
- 每个 Feign 调用提供**降级方法**（`fallback` / `fallbackFactory`），返回兜底值或明确错误，不允许把异常抛穿到用户侧。
- 降级策略分级：
  - **可缓存数据**：读缓存兜底（本地缓存 → Redis → DB，见 [数据与存储设计](architecture-data.md)）。
  - **可省略数据**：非核心字段返回默认值/空，接口降级为「部分成功」并在响应头标记。
  - **核心数据**：直接返回明确错误码（如 `503 SERVICE_UNAVAILABLE`），由前端提示稍后重试。
- 限流与熔断规则统一在控制台/配置下发，规则变更实时生效，禁止写死在代码里。

## 5. 分布式事务（Seata AT + 本地事务）

### 5.1 原则：能本地就不分布式

- **优先本地事务**：单库内多表操作用 `@Transactional`，不引入分布式事务。
- **跨服务写一致性**才使用 Seata（AT 模式，`ruoyi-common-seata` 接入）：
  - AT 模式适合大多数 CRUD 场景（无侵入、自动回滚）。
  - 复杂补偿场景可选 TCC / Saga（预留资源、业务补偿），需单独设计。
- 事务边界要小：**不在事务内做远程调用、外部等待、文件上传**，避免长事务锁表（见 [数据与存储设计](architecture-data.md) 事务边界）。

```
Seata TC(8091) 协调
System(事务发起) ──AT──► Workflow(审批创建) ──AT──► Job(任务)
全部 commit / 任一失败全局 rollback（undolog 自动补偿）
```

### 5.2 最佳实践

- 全局事务超时与重试上限显式配置；避免大事务（数据量 > 数千行）进全局事务。
- 事务发起方捕获异常并转换为业务错误码，不泄漏 Seata 内部异常。
- 对无法保证强一致的场景（如发消息、缓存更新），采用「本地事务 + 消息/定时补偿」的最终一致方案。

## 6. 兜底与降级策略

| 场景 | 兜底策略 |
|------|----------|
| 配置中心不可用 | 本地 `local-env.yml` / 本地缓存配置兜底（`optional:` import） |
| Redis 不可用 | 读 DB + 直接写库，禁用缓存旁路时降级为直查（加限流防击穿） |
| 下游服务熔断 | fallback 返回兜底值 / 排队提示 |
| 定时任务失败 | 失败重试 + 告警，任务记录状态机（见 `ruoyi-job`） |
| 文件服务不可用 | 返回明确错误，前端提示稍后重试（不静默丢文件） |
| 第三方网关超时 | 异步回调 + 轮询补偿，禁止同步阻塞主链路 |

> 所有降级必须**可观测**：降级发生即打日志 + 指标（降级次数），并能在控制台一键恢复/关闭降级开关。

## 7. 异常体系与错误码规范

### 7.1 异常体系

- 业务异常**禁止裸 `RuntimeException`**，统一使用 `ServiceException`（见 [AGENTS.md](../../AGENTS.md) 4.5）。
- 模块专用异常放 `ruoyi-common-core` 的 `exception/` 包，并在 `GlobalExceptionHandler` 注册对应 `@ExceptionHandler`。
- 全局处理链：`ServiceException` → 参数校验异常 → 权限/认证异常 → 数据访问异常 → 兜底 `Exception`（不向客户端泄漏堆栈与内部信息）。

### 7.2 错误码规范

| 段位 | 范围 | 含义 |
|------|------|------|
| `A` 认证 | `A1000~A1999` | 未登录、令牌过期/无效、刷新失败 |
| `P` 权限 | `P2000~P2999` | 无权限、数据越权、资源归属冲突 |
| `B` 业务 | `B3000~B3999` | 业务规则不满足（状态机、余额不足、重复提交） |
| `C` 参数/校验 | `C4000~C4999` | 参数缺失、格式错误、越界 |
| `D` 数据/存储 | `D5000~D5999` | 记录不存在、并发冲突（乐观锁）、唯一键冲突 |
| `E` 基础设施 | `E6000~E6999` | 依赖不可用、超时、熔断、限流 |
| `S` 系统 | `S9000~S9999` | 未预期异常（内部错误，不返回堆栈） |

> 约定：错误码**稳定且可检索**，接口同时返回 `code + msg + data`；前端按码段统一提示与处理（如 `E6xxx` 走「稍后重试」交互）。

## 8. 空值 / 并发 / 边界处理

- **空值**：DTO/VO 使用强类型；集合返回空集合而非 `null`；Service 层对可能为 null 的查询结果显式判空（`Optional` / 空对象模式）。
- **并发**：
  - 写并发：乐观锁（版本号）或 `SELECT ... FOR UPDATE`（短事务）二选一，按场景权衡。
  - 幂等并发：幂等表唯一键兜底（`INSERT ... ON DUPLICATE KEY`），防止并发穿透。
  - 状态流转：状态机校验（`WHERE status = 期望值`），禁止无条件覆盖。
- **边界**：分页参数钳制、数值范围校验、金额用 `BigDecimal`（禁止 `double`）、时间边界（跨日/跨月/时区）显式约定 UTC+8。
- **资源清理**：临时文件、上传分片、超时任务必须有清理机制（定时任务 + TTL）。

## 9. 缓存穿透 / 击穿 / 雪崩防护

| 风险 | 现象 | 防护 |
|------|------|------|
| 穿透 | 查不存在的数据，打到 DB | 空值缓存（短 TTL + 随机）；布隆过滤器拦截热点不存在 key |
| 击穿 | 热点 key 过期瞬间并发打 DB | 互斥锁重建缓存（`SETNX` 锁 + 双检）；热点 key 不设过期（逻辑过期） |
| 雪崩 | 大量 key 同时过期 / Redis 宕机 | TTL 加随机抖动；Redis 高可用（哨兵/集群）；本地缓存兜底 |

> 缓存 KEY 设计与一致性见 [数据与存储设计](architecture-data.md) 第 5、6 节。

## 10. 消息可靠性（若引入 MQ）

- **生产**：事务消息（本地事务表 + MQ 发送）保证「业务成功 → 消息必达」。
- **消费**：手动 ACK + 消费幂等（业务主键去重），失败重试进入死信队列（DLQ）并告警。
- **顺序**：仅对必须有序的场景（如单据状态流转）使用分区键保证局部有序，其余场景不承诺全局顺序。
- **积压**：监控队列深度，积压告警并支持扩容消费者。

## 11. 混沌与压测要点

- **压测**：
  - 明确容量目标（如 500 QPS，P95 ≤ 300ms），压测环境与生产同构。
  - 覆盖：单接口压测、链路压测（网关→服务→DB/Redis）、故障注入压测。
  - 观察指标：QPS/TPS、RT（P50/P95/P99）、错误率、线程池/连接池水位、GC。
- **混沌（Chaos）**：定期演练——杀一个服务实例、Redis 故障、DB 慢查询注入、网络延迟，验证熔断/降级/重试是否符合预期（见 [05-ops](../process/00-overview.md) 运维阶段）。
- 演练结果输出「故障复盘 + 改进项」，纳入下一迭代。

## 12. SLA 与容错矩阵

### 12.1 SLA 目标（示例基线）

| 指标 | 目标 |
|------|------|
| 可用性 | 99.9%（月停机 ≤ 43 分钟） |
| 响应时间 | P95 ≤ 500ms，P99 ≤ 2s（核心接口） |
| 错误率 | 5xx 占比 ≤ 0.1% |
| 恢复时间 | RTO ≤ 30 分钟，RPO ≤ 5 分钟（见 [数据与存储设计](architecture-data.md) 备份） |

### 12.2 容错矩阵

| 故障点 | 检测 | 应对 | 恢复 |
|--------|------|------|------|
| 服务实例宕机 | Nacos 心跳 + 探活 | 负载均衡摘除，其他实例接管 | 自动扩容/拉起 |
| 数据库故障 | 连接池告警 | 只读降级/缓存兜底，写接口返回 E6xxx | 主从切换/备份恢复 |
| Redis 故障 | 命令超时/哨兵告警 | 旁路直查 DB（限流防击穿） | 哨兵自动切换 |
| 下游服务故障 | Sentinel 熔断 | fallback 降级 | 熔断窗口后半开试探 |
| 消息积压 | 队列深度告警 | 扩容消费者/降级非核心消费 | 积压清理脚本 |
| 网络分区 | Feign 超时 | 重试（幂等）+ 熔断 | 网络恢复自动回稳 |

## 13. 容错检查清单

- [ ] 每个 Feign 调用配置超时 + 重试（仅幂等） + 降级 fallback
- [ ] Sentinel 熔断/限流规则已配置并下发，降级可观测、可一键关闭
- [ ] 写操作（支付/审批/回调）实现幂等，状态流转使用乐观锁
- [ ] 异常统一走 `ServiceException` + `GlobalExceptionHandler`，错误码符合 §7.2 规范
- [ ] 缓存三防（穿透/击穿/雪崩）措施已落实
- [ ] 事务边界清晰：不在事务内做远程调用/等待；跨服务强一致走 Seata AT
- [ ] 压测/混沌演练结果有记录，SLA 指标有监控看板

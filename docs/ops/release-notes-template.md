## 4. 数据库变更

| # | SQL 脚本 | 目标库 | 说明 | 向后兼容 |
|---|----------|--------|------|----------|
| 1 | `sql/V1.2.0__add_sys_user_dept_index.sql` | ry-cloud | 用户表部门索引 | 是 |
| 2 | `sql/V1.2.0__flowable_upgrade.sql` | ry-flowable | Flowable 表升级 | 是 |

**执行原则**：

- 迁移**只前向、禁止回退**（Flyway 语义），脚本按版本号递增命名：`sql/<version>__<desc>.sql`。
- 先在 staging 演练，再在 prod 执行；执行前完成数据库备份（见[运维手册 §6](ops-handbook.md)）。
- DDL/DML 必须可重复校验：脚本执行前后对比表结构 / 行数，并记录执行时间与执行人。

## 6. 部署说明

**构建**：

```bash
mvn -pl ruoyi-auth,ruoyi-system -am clean package -DskipTests   # 按本次涉及模块调整
cd ruoyi-ui && npm run build:prod                                # 前端构建（如有变更）
```

**部署顺序**（详见[运维手册 §2](ops-handbook.md)）：

1. 基础设施确认健康（Nacos / MySQL / Redis / MinIO / Seata / Sentinel）。
2. 执行 §4 数据库迁移。
3. 发布 §5 配置变更。
4. 灰度 1 个实例 → 冒烟 → 全量滚动（业务服务先行，网关最后）。
5. 前端产物替换并刷新缓存。

## 7. 回滚方案

| 场景 | 回滚动作 | 负责人 |
|------|----------|--------|
| 代码缺陷（P0/P1） | 回退镜像/JAR 至上一版本，滚动重启 | 运维 |
| 配置异常 | 恢复 Nacos 上一版本配置（发布记录留档） | 运维 |
| 数据问题 | **禁止执行反向 SQL**；走人工补偿脚本 + 评审 | 开发 + 运维 |
| 前端异常 | 回退静态资源版本 | 前端 |

**回滚触发条件**：灰度验证未过，或全量后出现 P0/P1 故障且 30 分钟内无法修复。

**数据兼容原则**：新版本引入的结构变更必须保证旧版本代码可读（向后兼容），否则需制定「代码 + 数据」联合回滚方案并经评审。

## 8. 验证清单（Checklist）

> 全量后逐项勾选，全部通过才算发布完成。

**基础健康**

- [ ] 网关 `http://127.0.0.1:8080/actuator/health` 返回 UP
- [ ] 本次涉及服务全部注册到 Nacos，实例数正确
- [ ] 未涉及服务无异常重启（`docker ps` / 日志抽查）

**核心链路**

- [ ] 登录 / 登出 / 刷新 token 正常
- [ ] 本次变更功能按用例回归通过（关联测试报告）
- [ ] 定时任务按计划执行无重复（如涉及 ruoyi-job）
- [ ] 文件上传 / 下载正常（如涉及 ruoyi-file）
- [ ] 审批流程可正常发起与推进（如涉及 ruoyi-workflow）

**数据与配置**

- [ ] SQL 迁移已执行且校验通过（表结构/行数核对）
- [ ] Nacos 新配置已生效（页面验证或接口验证）
- [ ] 数据库备份完成且可恢复

**监控与安全**

- [ ] 无 P0/P1 告警未闭环，告警规则无新增误报
- [ ] 日志无敏感信息泄露、无异常堆栈刷屏
- [ ] 回滚方案已就绪且回滚负责人确认

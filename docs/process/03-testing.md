# 测试阶段（Testing）

> 本文档定义 **「测试策略 → 用例设计 → 测试执行 → 缺陷管理 → 回归 → Gate G3」** 阶段的规范与产出，输入来自 [02-development.md](02-development.md)（已合并的代码与测试）。
> 关联文档：[流程总览](00-overview.md) · [安全架构](../architecture/architecture-security.md) · [AGENTS.md](../../AGENTS.md)（§6 测试要求） · [workflow-management](workflow-management.md)（CI 触发）

---

## 1. 阶段目标与出口条件

| 项 | 说明 |
|----|------|
| 输入 | 已过 G2 的代码、单测、集成测试、设计文档（验收标准） |
| 产出 | 测试计划、用例集、缺陷报告、回归报告、测试报告 |
| 出口条件（Gate G3） | **测试通过、缺陷清零（或达成上线阈值）**，见 §10 |

---

## 2. 测试策略

按测试金字塔分层，层级越低执行越频繁、成本越低：

| 层级 | 工具/方式 | 执行时机 | 负责人 |
|------|-----------|----------|--------|
| 单元测试 | JUnit5 + Mockito（Surefire） | 每次提交/PR（CI） | 开发 |
| 集成测试 | Spring Boot Test + 真实依赖（Failsafe，`*IT`） | PR 合并前、测试阶段 | 开发/QA |
| 接口测试 | HTTP 工具/脚本，走网关 `/prod-api` | 测试阶段每日 | QA |
| 契约测试 | OpenAPI 契约 + Feign 消费方校验（spring-cloud-contract 可选） | 接口变更时 | 开发 |
| 端到端（E2E） | Playwright/Cypress 或手工冒烟脚本 | 发布前 | QA |
| 性能测试 | JMeter / Gatling | 涉及高并发/大表功能时 | QA/性能组 |
| 安全测试 | 越权用例、脱敏校验、OWASP 基线扫描 | 每版本至少一轮 | QA/安全 |

> 原则：**先单测、后集成、再接口/E2E**；CI 至少跑「lint + 单测 + `mvn verify`」（§8）。

---

## 3. 测试环境说明

| 环境 | 用途 | 数据特点 | 说明 |
|------|------|----------|------|
| local | 开发自测 | 开发者本机数据 | 凭 local-env.yml 覆盖 |
| dev | 集成环境 | 可重置 | 合并后自动部署 |
| test | 测试环境 | **数据固定**，供 QA 回归 | 缺陷复现、回归主场地 |
| staging | 预生产 | 与生产同构 | 灰度演练、性能摸底 |
| prod | 生产 | 真实数据 | **禁止任何测试写入**（§9） |

> 测试用例先标环境（如 `env: test`）；跨环境差异（网关地址、账号）写入测试计划，避免用例与环境强耦合。

## 4. 测试用例设计

### 4.1 用例方法

- **等价类划分**：每个输入划分有效/无效等价类，每类至少一条用例（如状态 `0/1/2`，非法值 `-1`）。
- **边界值分析**：必测上下边界与边界外 1 单位（分页 `pageSize` 上限 100、字符串 `@Size` 边界）。
- **场景法**：按业务主流程/备选流/异常流设计端到端场景（登录 → 授权 → 发起流程 → 审批 → 归档）。
- **错误推测**：结合经验补测：重复提交、并发办理、超时、断网重试。

### 4.2 用例模板字段

```
用例编号 | 关联需求/接口 | 前置条件 | 步骤 | 预期结果 | 优先级 | 环境 | 执行结果
```

- 编号规则：`TC-<模块>-<序号>`（如 `TC-WORKFLOW-001`）；优先级 P1 必测 / P2 应测 / P3 可选。
- 用例须可追溯到设计文档的验收标准（[01-design.md](01-design.md) §2.2），保证"验收标准可测"。

## 5. 缺陷管理

### 5.1 分级

| 级别 | 定义 | 示例 | 处理时限 |
|------|------|------|----------|
| P0 | 阻塞性：系统不可用/数据丢失/资金错误 | 登录失败、审批数据错乱 | 立即，停线修复 |
| P1 | 严重：核心功能不可用但有绕行方案 | 主流程报错、权限失效 | 当日 |
| P2 | 一般：非核心功能缺陷 | 列表字段显示错误 | 本迭代 |
| P3 | 轻微：体验/文案问题 | 提示语不友好 | 可排期 |

### 5.2 流转状态

```
新建(New) → 指派(Assigned) → 修复(Fixed) → 验证(Verified) → 关闭(Closed)
                 └── 无法复现/非缺陷 → 拒绝(Rejected)
                 └── 验证不通过 → 重新打开(Reopened)
```

- 缺陷单必填：级别、复现步骤、期望/实际结果、日志与截图、关联用例/提交。
- P0/P1 修复后**必须回归**原用例及相邻场景；关闭需 QA 确认。

## 6. 回归与冒烟

- **冒烟测试（冒烟集）**：每次新版本部署后先跑，通过才进入正式测试。固定冒烟集覆盖核心链路：
  - 登录/令牌刷新、用户/角色/菜单 CRUD 与权限生效、字典/参数读取、工作流发起→审批→归档、文件上传下载。
- **回归测试**：版本发布前对受影响的既有功能全量回归；变更影响面由「接口契约 diff + 依赖分析」确定（跨服务接口变更须回归消费方）。
- 回归通过标准：冒烟集 100% 通过，受影响用例无新增 P0/P1 缺陷。

---

## 7. 覆盖率要求

- 使用 JaCoCo（`mvn verify` 时生成）度量单测覆盖率：
  - **新增代码行覆盖率 ≥ 70%**，核心逻辑（权限、状态流转、金额计算）**分支覆盖率 ≥ 60%**。
  - 存量代码不设硬性门槛，但被本次变更触碰的代码必须补齐用例。
- 覆盖率报告路径：`<module>/target/site/jacoco/index.html`；未达标视为 G2/G3 阻塞项。
- 关键路径必须有测试：鉴权、分布式事务（Seata）、幂等、脱敏、异常分支。

## 8. CI 集成

在 `.github/workflows/`（如 `ci.yml`）中配置，提交/PR 触发：

```yaml
# 要点：并行跑后端与前端检查，任一失败即阻断合并
- name: 前端 Lint + Build      # npm run lint && npm run build
- name: 后端单测               # mvn test -pl <affected> -am
- name: 后端构建验证           # mvn verify（含 JaCoCo、Failsafe 集成测试）
```

- 提交/PR 触发：lint + 单测 + `mvn verify` + `npm run build`（[流程总览](00-overview.md) §3.3）。
- 主分支合并触发：构建镜像 → 部署 dev；打 tag 触发：staging → prod（灰度）。
- **CI 全绿是合并与进入测试阶段的必要条件**，与 [02-development.md](02-development.md) §9 的 G2 联动。

---

## 9. 测试数据管理

- **红线：禁止任何测试写入污染生产库**；测试只允许在 local/dev/test 环境写数据。
- 测试库与开发库命名以 `sql/` 为准；造数脚本放 `sql/test-data/`，可重复执行（幂等）。
- 从生产导出的脱敏数据用于测试时，手机号/身份证/银行卡必须按 `ruoyi-common-sensitive` 规则脱敏（[AGENTS.md](../../AGENTS.md) §4.6）。
- 集成测试使用 `@Transactional` 回滚或独立 schema，测试结束恢复现场；数据库查询一律走 MCP 只读（[AGENTS.md](../../AGENTS.md) §3）。

## 10. Gate G3 标准

- [ ] 冒烟集 100% 通过
- [ ] 计划内用例全部执行，P0/P1 缺陷清零（P2 有明确修复计划与排期）
- [ ] 回归完成：受影响范围无新增 P0/P1
- [ ] 覆盖率达标（§7），测试报告已输出（§11）
- [ ] 性能/安全测试（如适用）结论无阻塞项
- [ ] 缺陷单流转状态与系统一致（无遗留 Open 的 P0/P1）

> 达成 G3 后进入 [04-release.md](04-release.md)（生产验收）。

## 11. 测试报告模板

测试报告存放 `docs/ops/release-notes/` 或随版本发布单提交：

```markdown
# <版本> 测试报告

## 1. 概览
- 测试范围 / 测试环境 / 测试周期 / 执行人
- 结论：通过（可发布）/ 有条件通过 / 不通过

## 2. 用例统计
| 计划 | 执行 | 通过 | 失败 | 阻塞 | 通过率 |
|------|------|------|------|------|--------|
| 120  | 118  | 115  | 2    | 1    | 97.5%  |

## 3. 缺陷统计
- 按级别分布（P0/P1/P2/P3）、状态分布、遗留问题清单及处理计划

## 4. 覆盖率
- 新增行覆盖率 / 核心分支覆盖率（附 JaCoCo 报告链接）

## 5. 专项测试结论
- 性能 / 安全 / 兼容性（如执行）

## 6. 风险与建议
- 遗留风险、上线注意事项
```

## 12. 常用命令速查

```bash
# 单测（Surefire，JUnit5 + Mockito）
mvn test -pl ruoyi-modules/ruoyi-system -am -q
mvn test -pl ruoyi-modules/ruoyi-system -am -Dtest=SysUserServiceImplTest -q

# 集成测试（Failsafe，类名 *IT，连真实依赖）
mvn verify -pl ruoyi-modules/ruoyi-system -am -DskipITs=false

# 全量构建验证（含 JaCoCo 覆盖率报告）
mvn clean verify

# 接口冒烟：走网关
curl -X POST http://localhost:8080/prod-api/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"***","code":"***","uuid":"***"}'
```

> 命令中的模块路径按实际 Maven 模块调整；涉前端变更时配合 `npm run lint` / `npm run build` 一起校验。
